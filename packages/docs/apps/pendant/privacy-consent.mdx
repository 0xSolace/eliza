The pendant is an ambient microphone. Operators must get consent from people who may be recorded and must comply with applicable law before connecting or testing it. The system does not obtain third-party consent on the operator's behalf.

## Capture Starts After Connect

Ambient capture starts only after the user explicitly selects Connect and completes the BLE chooser or native Android device picker. Once connected, the base branch keeps listening while connected.

The transcript surface includes pause and resume. Pause drops new BLE audio before VAD, resets the local frame/VAD buffers, invalidates any in-flight ASR tail so late results cannot commit after pause, and records the paused state on the server session. Future continuous vendor streams must wire pause to the network boundary by closing or muting the stream.

## Device Emission Boundary

The reference device emits audio only while a BLE central is connected and subscribed to the audio notify characteristic. If there is no active central subscription, the app does not receive audio notifications.

Disconnecting in the app tears down notifications, disconnects GATT, releases the decoder, and returns the UI to idle.

## Local Processing Boundary

The app decodes Opus and segments utterances locally in the app process:

- BLE notifications are reassembled in the app.
- Opus frames are decoded in the app.
- VAD segments utterances in the app.
- The utterance is encoded into a WAV payload in the app.

ASR is not performed by the browser itself in this branch. `transcribeLocalInferenceWav` posts the WAV as base64 JSON to `/api/asr/local-inference`. A loopback backend URL on the agent host does not prove ASR ran on the Light Phone or client device, especially when the agent itself is remote. The session UI therefore reports cloud/remote ASR until a future ASR response includes authenticated end-device provenance.

Verify the actual deployment policy, network route, model provider, response provenance, and logs before making privacy claims.

## Agent and Storage Path

The server-accepted resolved segment is the canonical utterance. That committed segment can fan out to the follower transcript, a session-tagged `VOICE_DM` turn in the same Eliza agent, and opt-in insights. From that point onward, the agent turn follows the configured model, logging, memory, conversation, and storage path for that deployment.

Pendant session delete removes the authoritative session record and cascades to pendant insight memories that cite the session's source segment IDs plus session-tagged pendant `VOICE_DM` turns. A local Clear action only removes the offline optimistic browser cache and must not be described as server-side deletion. Verify deployment retention policy before collecting real speech.

## Error Visibility

Pendant ASR errors and discarded silence are distinct states. ASR failures surface as dropped/error segments while listening resumes; silence discard does not imply backend failure. Capture frontend status, content-free framing metrics such as packet/frame counts and dropped-tail counts, server route logs, and backend ASR logs during tests without logging transcript content.

## Operating Rules

- Tell participants when the pendant is connected and listening.
- Pause or disconnect when capture should stop.
- Do not use a pendant in places where recording is prohibited.
- Do not test with sensitive speech unless the deployment retention and ASR backend are verified.
- Treat transcripts as agent messages governed by the same model and storage policy as other voice turns.
- Do not claim anonymous voice clusters identify people. Any speaker alias must be explicitly assigned by a user.
- Treat follower views as read-only displays of server snapshots unless the UI explicitly exposes a mutation.
